# Аудит Соответствия ТЗ

Дата фиксации: `2026-07-25`

## Статусы
- `done` — реализовано в коде и используется.
- `partial` — есть часть функционала, но ТЗ закрыто не полностью.
- `todo` — в текущем коде не реализовано.

## MVP
- `done` Логин/логаут.
- `done` Создание, переименование, перемещение и удаление виртуальных директорий.
- `done` Загрузка файлов в выбранную директорию.
- `done` Drag-and-drop загрузка в браузере.
- `done` Просмотр содержимого директорий.
- `done` Переключение `list/grid`.
- `done` Просмотр изображений и видео без скачивания.
- `done` Скачивание файла.
- `done` Скачивание директории архивом.
- `done` Создание публичной ссылки на файл или директорию.
- `done` Срок действия ссылки.
- `done` Защита ссылки паролем.
- `done` Закрытый доступ по умолчанию.
- `done` Светлая и темная тема на уровне UI-токенов.
- `partial` Регистрация пользователей только администратором.
Сейчас админ может создавать пользователей напрямую. Не хватает invite-based закрытой регистрации и отдельного управления регистрацией.

## Архитектура
- `done` `service/repository/entity/dto/converter` слой без JPA.
- `done` MVC-контроллеры для `auth`, `cabinet`, `control`, `share`.
- `partial` `web/api` слой для ajax-операций.
Основная логика пока завязана на MVC-формы и HTML redirect flow.

## Данные и хранение
- `done` Модель `users/folders/files/share_links/audit`.
- `done` Дерево директорий на `parent_id` и `path_key`.
- `partial` ТЗ больше не должно считать `agdrv_file_content` основным runtime-хранилищем.
Фактическая реализация использует файловое хранилище на диске. Legacy BLOB-контент мигрируется наружу. Это нужно считать целевым поведением и закрепить в ТЗ.
- `todo` `agdrv_user_invites` или `agdrv_registration_requests`.

## UX
- `done` Sidebar, toolbar, breadcrumbs, file table, grid cards, modals, share flow.
- `partial` Левое дерево папок в sidebar.
Есть навигация и breadcrumbs, но нет полноценного дерева каталогов в боковой панели.

## Нефункциональные требования
- `done` Java 21 target в `pom.xml`.
- `done` PostgreSQL как основная БД.
- `done` Ограничение размера upload конфигурируется.
- `done` CSRF и session protection.
- `done` bcrypt для паролей.
- `done` Аудит действий и error handling.
- `partial` Потоковая выдача файлов без полной загрузки в память.
Часть ответов всё ещё строится через `byte[]`.
- `partial` Проверка MIME-типа и безопасных имён файлов.
Есть базовая работа с `mimeType` и именами, но нет жёсткой централизованной политики safe filename validation.

## Этапы Реализации
- `done` Этап 1. Основа.
- `done` Этап 2. Файловый менеджер.
- `partial` Этап 3. Preview и публикация.
Основной share/preview-функционал есть, но нужен API-слой и доводка хранения/streaming.
- `partial` Этап 4. Архивация и админка.
Архивация, аудит и user management есть. Не хватает управления регистрацией.
