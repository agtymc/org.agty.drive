# WebDAV

## Что это

AGTY/DRIVE позволяет включать WebDAV для отдельных папок. Для каждой папки создается собственный адрес подключения, отдельный логин и пароль, а также режим доступа:

- только чтение;
- чтение и запись.

Это удобно, если нужно подключить папку как сетевой диск в файловом менеджере, на рабочей станции или в стороннем клиенте.

## Как включить WebDAV

1. Откройте раздел `Файлы`.
2. Найдите нужную папку.
3. Нажмите на шестеренку у папки.
4. Выберите `Настроить WebDAV`.
5. Укажите:
   - логин;
   - пароль;
   - включен ли доступ;
   - нужен ли режим записи;
   - нужно ли переиздать адрес подключения.
6. Сохраните настройки.

После сохранения интерфейс показывает:

- адрес WebDAV;
- логин;
- режим доступа;
- пароль, если он был задан или изменен в этой операции.

## Что получает пользователь

Пример адреса:

```text
http://192.168.21.113:8080/dav-share/eb20dadf18494de1a7a94b2d3899dd3b/
```

Пример учетных данных:

```text
Логин: docs
Пароль: 12345678
```

Аутентификация выполняется через `HTTP Basic Auth`.

## Проверка в браузере

Если открыть адрес папки в браузере, сервер вернет HTML-страницу со списком содержимого папки.

Это удобно для быстрой ручной проверки:

- открывается ли папка;
- видны ли вложенные файлы и папки;
- работает ли логин и пароль.

Важно:

- браузер может кэшировать `Basic Auth`;
- для честной проверки авторизации лучше использовать приватное окно или `curl`.

## Проверка через curl

Проверка чтения:

```bash
curl -i -u docs:12345678 -X PROPFIND \
  -H 'Depth: 1' \
  http://192.168.21.113:8080/dav-share/eb20dadf18494de1a7a94b2d3899dd3b/
```

Ожидаемый результат:

- `207 Multi-Status` при корректных учетных данных;
- `401 Unauthorized` при неверных учетных данных.

Проверка открытия папки как обычного URL:

```bash
curl -i -u docs:12345678 \
  http://192.168.21.113:8080/dav-share/eb20dadf18494de1a7a94b2d3899dd3b/
```

Ожидаемый результат:

- `200 OK`;
- `Content-Type: text/html`.

Проверка записи:

```bash
curl -i -u docs:12345678 -T ./test.txt \
  http://192.168.21.113:8080/dav-share/eb20dadf18494de1a7a94b2d3899dd3b/test.txt
```

Ожидаемый результат:

- `201 Created` для нового файла;
- `204` или `201` в зависимости от сценария обновления;
- `403 Forbidden`, если доступ настроен как `только чтение`.

## Ubuntu KDE

Проще всего проверять через `Dolphin`.

В адресную строку можно вставить:

```text
webdav://docs:12345678@192.168.21.113:8080/dav-share/eb20dadf18494de1a7a94b2d3899dd3b/
```

Если схема `webdav://` не сработала, попробуйте:

```text
dav://docs:12345678@192.168.21.113:8080/dav-share/eb20dadf18494de1a7a94b2d3899dd3b/
```

Что проверить:

- открывается список файлов;
- скачивается существующий файл;
- в режиме записи создается папка или копируется файл;
- в режиме `только чтение` запись запрещена.

## Windows

Подключение можно проверить через `Проводник` или `Map Network Drive`, но на практике стабильнее сначала проверить через клиент вроде `Cyberduck`.

Адрес:

```text
http://192.168.21.113:8080/dav-share/eb20dadf18494de1a7a94b2d3899dd3b/
```

Данные:

- username: `docs`
- password: `12345678`

Если Windows ведет себя нестабильно, сначала проверьте:

- что по `curl` приходит `207`;
- что папка открывается в браузере;
- что сервер доступен по IP и порту из сети Windows-машины.

## macOS

В `Finder` используйте `Go` → `Connect to Server`.

Адрес:

```text
http://192.168.21.113:8080/dav-share/eb20dadf18494de1a7a94b2d3899dd3b/
```

Затем введите логин и пароль:

- login: `docs`
- password: `12345678`

## Рекомендуемые клиенты

Если нужна более предсказуемая работа, используйте:

- `Cyberduck`;
- `rclone`;
- Linux/KDE `Dolphin`;
- другие WebDAV-клиенты с поддержкой `Basic Auth`.

## Ограничения текущей реализации

- WebDAV включается для папок, а не для всего диска целиком.
- У каждой папки свой адрес подключения.
- Блокировки `LOCK/UNLOCK` реализованы в stateless-режиме для совместимости клиентов.
- Если в одной директории существуют файл и папка с одинаковым именем, WebDAV-путь становится неоднозначным.

## Безопасность

- Не публикуйте WebDAV-адрес и пароль в открытом виде.
- Для внешнего доступа лучше использовать `HTTPS` через reverse proxy.
- Для каждого получателя лучше создавать отдельную папку или переиздавать адрес подключения.
- Если есть подозрение на утечку, переиздайте адрес и смените пароль.
